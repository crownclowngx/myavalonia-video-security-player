# R1：SOLID 结构优化与质量门禁实施计划

> 编制日期：2026-09-06
>
> 适用项目：`myavalonia-video-security-player`
>
> 状态：R1.2、R1.3 已完成；R1.4 选定实现完成，资源与性能验收仍未通过；完整 R1 保持未验收。
>
> 工作方式：先讨论与制定文档，再按本文分批实施；全过程不使用 AIFLOW。
>
> 目标：保持现有产品行为，通过明确职责、依赖和状态所有权，降低维护成本，并建立可复现的测试与验收门禁。

## 1. 实施范围与基本约束

R1 包含基线采集、门禁完善、播放 ViewModel 职责调整、批次队列共同机制整理、播放核心有限拆分及文档验收。按依赖顺序实施，每批独立验证。R1.0–R1.2 构成第一个可交付闭环，后续批次继续按本文推进。

用户已于 2026-09-06 要求开始执行。实际改动和验证以本文末尾记录及 [R1 实施设计与验证记录](../reference/R1-IMPLEMENTATION-AND-VALIDATION.md) 为准，未勾选任务不表示已完成。

### 1.1 必须遵守

1. SOLID 是设计与评审的首要约束，按职责和变化原因划分组件。
2. 设计模式朴素使用，优先沿用现有接口、组合、工厂、适配器和文件输出事务。
3. 新增、修改的代码注释使用中文；涉及并发、资源、安全和兼容行为时说明设计思路。
4. 修改必须有对应的行为测试，阶段完成必须有完整门禁证据。
5. 每批同步更新当前设计文档和本文实施记录，历史文档保留当时事实。
6. 不使用 AIFLOW；已有 Workflow Action 属于产品功能，其兼容性与回归测试仍须保留。

### 1.2 兼容边界

| 边界 | 必须保持的行为 |
| --- | --- |
| 容器格式 | SECVID03 的二进制布局、KDF、nonce、AAD、认证与随机读取语义保持兼容 |
| 文件操作 | 不覆盖已有输出、不删除源文件；失败或取消时清理本次拥有的 partial 文件 |
| 插件接入 | Plugin、Document、Action 标识及公开 SDK 接入方式保持兼容 |
| 用户数据 | 正式及 Standalone 数据路径、JSON 格式与恢复行为保持兼容 |
| UI | 四类文档、现有命令、快捷键、全屏、媒体库和队列交互保持一致 |
| 生命周期 | Document Scope 隔离；状态单一所有者；注入服务的释放责任明确 |
| 播放 | 换片失败补偿、最新用户意图优先、旧回调失效、原生命令串行顺序保持一致 |
| 安全与诊断 | 密码、密钥、明文和敏感路径不进入新增诊断证据 |

R1 不增加产品功能，不升级依赖，不修改密码学方案，不进行全仓命名清理，不引入新的通用框架，也不自动部署到用户正在使用的 Host。内部实现可调整，但公共契约的改变必须先更新计划、调用者清单和兼容策略。

## 3. SOLID 与设计规则

| 原则 | 实施规则 | 评审证据 |
| --- | --- | --- |
| S：单一职责 | 每个组件说明职责、状态所有权和变化原因；协调器负责用例顺序，具体规则由适当组件承担 | 职责表、依赖清单、行为测试 |
| O：开放封闭 | 仅在真实变化点引入扩展端口，新增适配实现不要求核心代码识别具体类型 | 无新增具体类型分支；适配器回归测试 |
| L：里氏替换 | 接口实现遵循相同的失败、取消、事件和释放约定；测试替身不能掩盖生产约束 | 契约测试以及真实适配集成测试 |
| I：接口隔离 | 子组件只访问所需能力；新增代码不通过完整 Owner 任意操作其他功能状态 | 调用者清单与依赖评审 |
| D：依赖倒置 | 业务编排依赖业务端口；原生、存储和调度细节留在适配边界 | 依赖方向测试与组合根检查 |

### 3.1 抽象的使用限制

- 优先使用组合。公开兼容外壳可以保留，但不新增多层基类体系。
- 只有存在外部副作用、替换需求或需要控制测试时序的边界才引入接口；纯计算可使用普通类或函数。
- 不以拆分文件、增加 `partial` 或包装转发属性数量作为职责优化成果。
- 不引入通用消息总线、CQRS、通用状态机或插件内部第二套 DI 框架。
- 加密与解密分别保留应用服务，不为复用少量代码合并为一个通用加解密用例。
- 确需抽象时，在注释与文档中解释调用者、变化点、所有权和未采用更简单实现的原因。

### 3.2 状态与生命周期

每个迁移的状态字段必须记录原所有者、新所有者、写入入口、通知方式、线程要求和关闭行为。同一状态只能有一个权威写入者，兼容属性与界面投影不得复制可独立修改的状态。

播放会话继续统一拥有用户意图、媒体切换事务和操作顺序。提取组件不能另建互不协调的锁、媒体代次或取消源。Document 关闭后不得出现回调写回、自动恢复播放或重复释放注入服务。

| 生命周期 | 文档隔离、取消、退订、重复释放安全、文件句柄及时释放 | `StandaloneRuntimeTests`、Host 测试、播放测试 | 检查实际所有者和释放次序 |
| 插件集成 | 四类文档可打开；依赖不泄漏；工作流不覆盖且保留源文件 | HostTests、HostUiTests、`Test-HostIntegration.ps1` | 必需场景必须实际执行 |
| 性能与资源 | 播放/切换响应、句柄与内存趋势、加解密和随机读取基线 | IntegrationHarness、ReleaseAcceptance、SecurityBenchmarks | 与同环境 R1.0 基线比较 |

### 5.1 测试实现要求

- 单元测试通过受控任务、假调度器、显式信号或事件队列控制时序，避免依赖固定休眠碰运气。
- 异步等待设置合理超时，超时报告应指明未达到的状态。
- 临时文件使用独立目录，测试释放自己创建的资源；不触碰用户视频与正式数据目录。
- mock 或 fake 只替换边界，不以“调用了某个内部方法”代替用户可观察行为断言。
- 真实播放器、文件系统和 SDK 的约束由集成测试验证，Headless UI 不替代 HWND 验收。
- 保留有价值的兼容契约测试，避免测试锁定可自由重构的私有实现细节。

### 5.2 覆盖率规则

1. 全局继续仅统计正式 `VideoSecurityPlayer.Plugin`，合并业务、UI、Host、Host UI 四套结果。
2. 固定下限保持行 72.59%、分支 48.12%；同口径 R1.0 基线若更高，后续执行不低于该已确认基线。
3. 新提取的纯业务/状态组件以行覆盖率至少 90%、分支覆盖率至少 80% 为目标并纳入门禁；没有可计数分支时记录不适用。
4. 取消、迟到回调、回滚、不覆盖和关闭后的行为必须有明确测试，不以百分比替代这些检查。
5. 对原生或 UI 适配器使用可观察行为与集成证据验收。确实无法覆盖的路径逐条登记原因及替代验证，不能通过扩大排除规则、降低基线或删除断言通过门禁。
6. R1.0 先确认覆盖率稳定性；发现抖动应固定测试时序与采集方式，再进入重构。

## 9. 风险与回退

| 风险 | 控制措施 | 回退范围 |
| --- | --- | --- |
| 拆分产生双份状态或漏通知 | 状态所有权表、属性通知与 UI 测试 | 回退当前功能组件迁移 |
| 加解密复用错误统一了业务差异 | 先列差异，再提取机制；分别执行行为测试 | 回退共享机制及对应接线 |

| 门禁显示通过但场景未执行 | 前置条件、执行计数、报告存在性与结果状态校验 | 修复门禁后重跑，不沿用旧报告 |
| 性能变化被环境噪声掩盖 | 同环境、固定场景和阈值、可比较基线 | 暂停相关重构，定位后再验收 |

每批保持可独立审查、可独立回退的改动集合。用户要求提交时按批次组织提交。回退只针对本阶段拥有的改动，先检查工作区，保留用户已有修改，不使用破坏性清理命令。
