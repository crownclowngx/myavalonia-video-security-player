# G1：SECVID03 格式与安全验证

> 实施日期：2026-07-23
>
> 适用范围：MySmallTools 安全视频业务、SECVID03 容器、MySmallTools.Tests 与安全基准工具
>
> 格式原则：SECVID03 的魔数、磁盘布局、PBKDF2、AES-GCM、nonce、AAD、块大小和 Tag 大小保持冻结

## 1. 完成目标

G1 在 G0 真实素材基线之上建立可重复的格式和安全证据：

- 业务代码先按 Container、Encryption、Decryption、Playback、Library 五个子域整理，Container 不反向依赖其他业务。
- 固定头布局由一个经过检查的 `Secvid03Layout` 值对象统一计算。
- 结构非法的容器在读取可变前缀、分配前缀缓冲区和执行 PBKDF2 前被拒绝。
- 固定向量同时经过生产写入/读取链路和不调用生产格式辅助方法的参考实现验证。
- 自动化覆盖边界长度、物理截断、固定头与前缀逐字节篡改、块交换、跨文件复制、公开区损坏、资源清理和路径安全。
- Release 基准记录 600,000 次 PBKDF2 的打开时延和冷态 1 MiB 块读取成本。

G1 没有引入新格式、旧格式兼容、密码持久化、数字签名或公开元数据认证。

## 2. 威胁模型

### 2.1 保护资产

| 资产 | 保护目标 |
| --- | --- |
| 视频主体明文 | 未持有密码时保持机密；认证失败时不返回部分明文 |
| 固定头与原视频前缀 | 检测任何未经授权的修改 |
| 视频块顺序和归属 | 防止块交换及跨文件复制 |
| 密码和派生密钥 | 不写入容器、队列、日志或诊断；派生密钥短生命周期并清零 |
| 明文导出 | 只在完整认证后提交，不留下可误用的 partial |
| 解析与播放进程 | 畸形长度不得触发超大分配、整数回绕、越界 Seek 或无界路径写入 |

### 2.2 攻击者能力

假设攻击者可以：

- 离线取得、复制、截断、追加或任意修改 `.secvid`。
- 构造固定头长度、偏移、块数、UTF-8 和公开区记录。
- 控制公开文件名、标题、描述和解密候选路径。
- 反复触发公开信息读取、密码验证、随机 Seek 和明文导出。
- 了解完整格式、实现和固定测试向量。

不假设攻击者能够直接控制进程、内核或硬件随机数生成器。

### 2.3 信任边界

```text
不可信文件系统输入
    │
    ├─ 固定头 ── 严格结构检查 ── PBKDF2/AES-GCM 固定头认证
    ├─ 公开区 ── 长度/UTF-8/CRC/零填充检查（不提供真实性）
    ├─ 明文前缀 ────────────────── 固定头 AAD
    └─ 密文块 ──────────────────── 块 nonce + 不可变摘要 + 块序号 AAD
                                          │
                                          └─ 已认证明文流 / 事务式导出
```

公开文件名、标题和描述位于密码学信任边界之外。CRC32 只能检测写入中断或意外损坏；攻击者可以重写公开数据并重新计算 CRC。

### 2.4 明确不抵御

- 低熵密码的离线猜测；600,000 次 PBKDF2 只能提高单次猜测成本。
- 已运行进程、管理员、内核、调试器、键盘记录器或内存转储攻击。
- 屏幕录制、播放期间的明文捕获和恶意媒体解码器漏洞。
- 完整有效旧容器的回滚或重放。
- 文件存在、物理长度、扩展名和公开元数据泄漏。
- 托管密码 `string`、交换文件、休眠文件和存储介质的可靠安全擦除。

结构合法但认证失败的文件仍会执行固定成本 PBKDF2；只有明显非法结构能够在 KDF 前拒绝。

## 3. 安全控制与证据

| 威胁 | 控制 | 自动化证据 | 剩余风险 |
| --- | --- | --- | --- |
| 伪造长度导致分配或回绕 | 40 字节前缀上限、集中 `checked` 布局计算、精确物理长度 | 最大前缀、`long` 溢出、截断/尾随测试 | 合法超大文件仍受文件系统资源限制 |
| nonce 计数器重复 | Header 使用 0，块使用 `1..uint.MaxValue`，块数上限固定 | 上界与上界加一测试 | 依赖每文件 salt/noncePrefix 的安全随机性 |
| 固定头或前缀篡改 | AES-GCM 空明文 + 完整固定头/前缀 AAD | 256 字节固定头和全部前缀字节逐一翻转 | 错误密码和篡改对外统一为认证失败 |
| 块交换或跨文件复制 | 不可变摘要和大端块序号进入每块 AAD | 块交换、跨文件复制测试 | 不检测完整有效文件回滚 |
| 未认证明文泄漏 | GCM 成功后才复制；失败时清零目标缓冲区 | 失败缓冲区清零测试 | 解码和播放期间明文必然存在 |
| 公开区被宣称可信 | API/XML/文档明确非认证；CRC 与视频认证解耦 | CRC 损坏仍可播放、合法重写测试 | 主动攻击者可伪造公开内容 |
| 失败残留输出或句柄 | 结构/固定头认证先于输出，partial finally 清理 | 无目录/无输出/无 partial、独占重开测试 | 进程被强制终止可能遗留可识别 partial |
| 派生材料驻留 | 认证上下文拥有并清零 key/digest | Dispose 清零测试 | 托管运行时可能保留不可控副本 |

## 4. 格式边界与实现结论

`Secvid03Layout` 统一计算原始长度、前缀、主体、加密偏移、块数和物理长度。非空块数使用：

```text
1 + (bodyLength - 1) / 1,048,576
```

从而避免向上取整公式的加法溢出。解析器执行顺序为：

1. 精确读取 256 字节固定头。
2. 校验魔数、版本、固定常量、正负号、40 字节前缀上限和保留区。
3. 严格解码扩展名 UTF-8。
4. 重新计算布局并精确匹配物理文件长度。
5. 读取最多 40 字节明文前缀。
6. 执行 PBKDF2 和固定头认证。

最大合法块数为 `uint.MaxValue`：nonce 计数器 0 保留给固定头，视频块使用 1 到 `uint.MaxValue`。这修正了旧解析器少接受一个合法块的边界，不改变已生成文件。

密码学职责集中在 `Secvid03Cryptography`；格式类不再派生密钥或构造 nonce/AAD。`ISecvid03EntropySource` 只作为内部非确定性边界，生产实现继续使用 `RandomNumberGenerator`，不会成为可插拔格式或公共扩展 API。

## 7. 安全发现

| 编号 | 严重度 | 发现 | 处理 | 兼容性 |
| --- | --- | --- | --- | --- |
| G1-F01 | 高 | 固定头可声明接近 `int.MaxValue` 的明文前缀，打开链路可能在 KDF 前申请超大数组 | 解析前强制现有生产规则的 40 字节上限 | 只拒绝当前生产器不会生成的非规范文件 |
| G1-F02 | 低 | 旧块数检查把最大合法值限制为 `uint.MaxValue - 1` | 修正为接受 `uint.MaxValue`，拒绝上界加一 | 放宽到文档已定义的 nonce 范围 |
| G1-F03 | 低 | 公开记录尾部非零填充未被读取器拒绝，可能保留旧公开文本 | CRC 通过后同时要求剩余 64 KiB 区域为零 | 现有写入器始终生成零填充 |

没有发现必须修改 SECVID03 磁盘布局、KDF、nonce、AAD 或认证规则的问题，G1 不需要另立格式版本。
