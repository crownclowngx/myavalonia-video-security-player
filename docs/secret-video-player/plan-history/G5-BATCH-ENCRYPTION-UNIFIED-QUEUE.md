## 1. 目标与边界

G5 将单文件加密页面升级为 Document-scoped 批量队列，并让加密和解密共享状态、重试、
移除、清理和两级取消语义。SECVID03 磁盘布局、PBKDF2、AES-GCM、nonce、AAD、块大小和
G2 不覆盖事务均未改变。

明确不包含：

- 并行加解密、暂停/恢复、断点续传和崩溃恢复。
- 后台常驻或持久化队列。
- 覆盖已有文件。
- 每项不同密码、递归目录导入或批量元数据模板。

## 2. SOLID 边界与设计意图

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `SequentialVideoQueueRunner<T>` | 严格顺序、取消当前/全部、失败隔离和总体进度 | 密码、SECVID03、路径或 UI |
| `VideoBatchEncryptionService` | 批次内输出分配、逐项预检和同卷累计空间 | 密码学和队列状态 |
| `VideoEncryptorService` | 单文件 G2 预检并调用流式加密器 | 批次交互 |
| `VideoDecryptionService` | 候选检查、名称净化、预检和单项解密 | 加密任务或 Document 命令 |
| 加密/解密 ViewModel | 队列修订、命令、UI 状态和当前 Document 密码 | 文件事务和密码学 |
| `OutputFileTransaction` | 唯一 partial、落盘、不覆盖提交和回滚 | 批次命名策略 |

运行器通过单项执行委托应用策略模式，但没有建立“万能加解密服务”。两个领域服务保持独立，
只共享不会随领域变化的编排语义。队列项目使用组合的 `VideoQueueItemStatusViewModel`，
而不是要求加密和解密模型继承同一业务基类。

## 3. 队列身份、状态与计划

每个项目在加入 Document 时取得一个 `Guid ItemId`。路径不是可靠身份：用户可能修改输出、
失败后重新添加相同输入，旧回调也可能在新批次开始后到达。因此进度必须同时匹配：

```text
Document operation generation + RunId + ItemId
```

状态流转为：

```text
Pending → Preflighting → Ready → Running → Succeeded
                       ↘ Failed
Running → Failed / Cancelled
Failed / Cancelled → Pending
Ready → Pending（输出、公开信息或策略变化）
```

“检查批次”捕获队列修订和不可变请求快照。“开始执行”只接受相同修订的计划。密码变化不使
计划失效，因为普通预检不执行 PBKDF2；输出、标题、描述、冲突策略和解密输出目录变化都会
使计划失效。

预检不是文件锁。计划阶段的安全改名只处理当时可见的冲突；如果另一个进程在执行前创建了
最终路径，单文件服务和 `OutputFileTransaction` 必须返回 `OutputConflict`，不得再次静默改名。

## 4. 取消、失败和关闭

运行器持有两个不同的取消源：

- 批次取消源：取消当前并停止后续项目。
- 当前项链接取消源：只取消当前项，等待其关闭流和清理 partial 后继续下一项。

单项失败只标记该项目并继续。取消当前后，为避免下一个项目令总体进度倒退，当前项的剩余
权重视为已经走完；取消全部保留停止时的实际进度，不伪造 100%。

Document Dispose 顺序为：

1. 标记释放并推进操作代次。
2. 清空密码和确认密码。
3. 取消预检和运行批次。
4. 清除等待身份集合，使未开始项不能进入执行委托。
5. 不在 UI 线程同步等待异步文件和密码学资源清理。

已成功提交的文件不属于队列回滚范围，关闭 Document 后继续保留。

## 5. 冲突与空间

公共策略只有：

- `Block`：冲突项目进入 `Failed/OutputConflict`。
- `GenerateUniqueName`：计划阶段分配 `name (1).ext` 等名称并显示 Warning。

加密默认严格阻止；解密为兼容 G2 默认安全改名。两者最终都不覆盖。

批量加密按输出卷根或 UNC 根累计精确容器长度，防止“每个文件分别放得下，但整个批次放不下”。
空间未知继续沿用 G2 Warning；已知累计不足只阻止超出容量的当前及后续相关项目。

## 6. 密码与错误边界

密码只保存在当前 Document 的绑定属性，并在运行器的单项执行委托中直接传给应用服务。
下列类型均无密码成员：

- 批量请求、不可变计划和预检项目。
- 队列状态、进度和运行结果。
- 加密/解密队列项目。

UI 只展示稳定失败代码和预定义安全消息。文件选择器和未知异常的原始 `Exception.Message`
不进入可复制的队列状态。

## 7. 注释标准

G5 新增的 public/internal 契约、关键状态字段和非显然分支均使用中文注释说明设计意图。
重点包括所有权、单消费者原因、两级取消、稳定身份、预检非锁、TOCTOU、不覆盖提交、
总体进度和 Dispose 不等待。注释不复述显然赋值或循环；旧注释在职责变化时同步更新。
