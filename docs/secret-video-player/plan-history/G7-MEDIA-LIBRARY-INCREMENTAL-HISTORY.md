# G7：媒体库、增量刷新与播放历史实施记录

> 实施日期：2026-07-25  
> 生产基线：Windows x64、.NET 10、SECVID03
> 结论：代码与本地自动化门禁完成；1,000 项真实窗口滚动签字留待 G8 组合验收

## 1. 交付范围

G7 在不修改 SECVID03 和安全播放流的前提下交付：

- 当前目录/递归子目录扫描，默认仍为当前目录；
- 文件名、公开标题、修改时间和上次播放时间排序；
- 可用性及未播放、播放中、已看完状态筛选；
- `FileSystemWatcher` 增量新增、修改、删除和改名；
- 有界事件通道、250ms 合并和事件风暴完整重扫；
- 最近目录、侧栏、库设置展开状态、排序、筛选、音量和倍速设置；
- 最多 1,000 条播放历史、完成判定、单项删除和全部清空；
- 历史位置原子加载和 Seek；主按钮恢复后暂停，双击或 Enter 明确激活时恢复后直接播放。
- 列表优先的渐进式界面：搜索、列表和主加载按钮常驻，目录、筛选、密码与历史操作集中到可折叠“库设置”。

密码、派生密钥、明文块、认证上下文、公开标题/描述、轨道和任务队列均不进入用户数据文件。

## 2. SOLID 边界

| 组件 | 单一职责 |
| --- | --- |
| `VideoLibraryScanner` | 枚举候选并读取同一种公开文件快照 |
| `VideoLibraryCatalogSession` | 拥有一个目录的 watcher、Channel、事件合并和重扫 |
| `VideoLibraryBrowserViewModel` | 把目录快照投影为搜索、筛选、排序后的 UI 集合 |
| `SecretVideoUserDataStore` | 串行化单一 JSON 文件的内存快照与原子提交 |
| `PlaybackHistoryCoordinator` | 将当前 Document 的播放快照低频转成历史 |
| `SecureVideoPlayer` | 在播放操作门内原子执行媒体提交和历史位置恢复 |

存储具体类同时实现三个窄接口：播放器只看音量/倍速，媒体库只看浏览设置，历史协调器
只看历史。存储是进程级单例，但 watcher、播放代次、密码和历史写入抑制保持 Document-scoped。

## 3. 文件身份与信任边界

历史键由规范化绝对路径、SECVID03 `FileId` 和原视频长度组成。修改固定容量的公开信息不会
改变身份；同路径替换为另一容器会因 FileId 改变而成为未播放项。

扫描无需密码即可读取 FileId，所以此时它只是不可信索引提示。媒体加载仍通过原有
PBKDF2/AES-GCM 固定头认证；历史匹配不能跳过密码验证或让公开元数据获得真实性。

## 4. 增量目录会话

监听器在初始扫描前启动。原始事件进入容量 512 的有界 Channel，由一个消费者合并：

- 250ms 内同路径事件合并；
- 新增/修改重新读取，删除移除，改名转换为删除旧路径和读取新路径；
- 临时占用按 100/250/500ms 重试；
- watcher 错误、Channel 溢出或 500ms 内超过 128 个唯一路径时，等待 500ms 后完整重扫。

浏览 ViewModel 对每次打开、递归切换和刷新使用新代次。旧代次即使忽略取消并返回迟到结果，
也不能写入新目录。关闭 Document 会取消扫描并释放 watcher 与 Channel。

列表内部以路径字典保存快照；搜索、筛选、排序后使用一次 Reset 替换可见范围，并显式使用
虚拟化面板，避免千文件排序触发千次布局。

界面采用渐进披露但不引入新的业务服务：展开状态属于媒体库设置，默认折叠并通过现有 JSON
存储延续到新 Document；View 只负责原生 Expander、最大高度和内部滚动。搜索清除命令只把
搜索文本设为空并重建内存投影，不调用扫描器。折叠摘要仅暴露“密码已输入/未输入”，密码
内容仍只存在于当前 Document，也不因选择目录、加载或播放而自动改变面板展开状态。

## 5. 用户数据和隐私

文件固定为：

```text
%LocalAppData%\MyAvaloniaManagement\MySmallTools\secret-video-player\user-data-v1.json
```

该文件以明文包含最近目录、媒体路径、播放位置和时间，能够暴露用户访问过哪些本地文件。
界面提供清除单项和清空全部历史；实现不保留损坏备份或第二历史缓存。

输入上限为 2 MiB。损坏、过大或版本不兼容时使用默认值并显示非阻断提示。写入在 500ms
窗口合并，通过同目录唯一 partial、落盘刷新和覆盖移动提交。历史按上次播放时间只保留最近
1,000 条。

`IsLibrarySettingsExpanded` 是 `user-data-v1.json` 的可选 UI 字段，不提升版本；旧文件缺少该
字段时按 `false` 读取，因此升级后默认折叠，同时不会丢失目录、排序、筛选或侧栏状态。

短于 10 分钟的媒体达到 95% 视为完成；更长媒体达到 95% 或剩余不超过 30 秒视为完成。
完成项保留状态但恢复位置为零。播放中每 5 秒保存，并在暂停、停止、结束和切换时补写。
清除当前媒体后，本播放代次被抑制，直到重新加载，防止内存快照把已删除历史写回。

## 6. 历史恢复

`ISecureVideoPlaybackSession.LoadAtPositionAsync` 在同一个媒体切换操作门内完成：

```text
密码验证与候选解析
→ 提交新媒体
→ 限制并恢复历史位置
→ 发布 Ready
```

该用例不会调用 `Play()`。Seek 失败属于可丢弃的历史体验问题：媒体保持 Ready，回退开头并
显示稳定提示，不回滚已经认证成功的新媒体。上一项、下一项和连续播放仍保持 G6 的显式播放语义。

列表双击或按 `Enter` 是另一种明确的用户意图。它通过
`LoadAtPositionAndPlayAsync` 在同一操作门内完成认证、身份复核、Seek 和 Play；未完成记录
从历史位置续播，已完成或无历史记录从头播放。FileId 或原视频长度不一致时跳过旧位置；
Seek 失败时回退开头、显示非阻断提示并继续播放。主按钮仍调用前一种暂停用例，自动恢复最近
目录也不会加载或播放媒体。
