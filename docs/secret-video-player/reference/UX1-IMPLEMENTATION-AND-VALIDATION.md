## 1. 本轮实施约束

用户于 2026-09-15 授权按方案开始实施并分批提交 Git，同时明确：

1. SOLID 为首要设计约束，按变化原因区分界面、交互策略、应用协调与底层业务职责。
2. 设计模式朴素使用，优先组合已有服务，不引入通用框架或重复的业务状态。
3. 新增和修改的注释使用中文；涉及取消、并发、状态所有权、资源及兼容边界时解释设计思路。
4. 补齐本地单元测试和开发门禁，同步更新功能说明及本专用文档。
5. 不使用 AIFLOW，不使用 Windows CI，不执行发布门禁；发布阶段再执行相关门禁。
6. 每批提交包含具体的 Git title 和 description。测试结果只陈述实际执行证据。

本轮开发验证采用 Debug 构建、业务单元测试、Headless 界面测试和新增组件覆盖率；不调用 R1 Full、Host 打包验收、ReleaseAcceptance、Windows CI 或部署脚本。原生播放体验的本地专项验证与发布门禁分别记录。

## 4. 设计与兼容说明

- `PlaybackResumePolicy` 是无状态规则，只判断历史数值和格式化时间，不读取文件或控制播放。
- `SingleVideoSourceViewModel` 通过扫描、历史存储和历史协调器窄接口接入续播；实际媒体加载使用现有原子播放接口。
- `LibraryDocumentCoordinatorViewModel` 保存最新待输入意图；取消提升代次、清除目标并取消令牌，迟到完成不能覆盖当前状态。
- `VideoLibraryItemViewModel` 将实时状态作为文档投影，历史快照与当前播放标识分别显示；只在状态或列表变化时更新标识。
- 界面主操作变更属于方案明确要求的产品行为调整，保留“仅加载”以承接原有暂停加载意图。
- 单文件和媒体库复用历史策略；密码及正在执行的请求归属各自 Document。
- 原加解密、输出事务、容器格式、稳定标识和 Workflow Action 继续复用。
- 现有 `.gitignore` 本地改动与本任务无关，不纳入提交。
