## 1. 本次修订依据

在理解工程后，按用户要求优先处理交互和功能。SOLID、朴素组合、详细中文注释、单元测试与同步专用文档作为实施约束。开发使用 Debug 本地检查；不使用 AIFLOW、Windows CI 或发布门禁。

本文记录实施中确认的交互细节及能力边界；其他目标沿用 v1.0。文档版本与插件发布版本分别管理，本次不调整发布版本和依赖版本。

## 2. 已落地的主要流程

1. 主按钮、双击和 Enter 使用同一播放意图；保留“仅加载”和“从头播放”。缺少密码时保留最新意图，明确确认后执行，取消与换片使旧请求失效。
2. 单文件与媒体库共享历史。历史“未看完”与正在播放分别展示；媒体库提供继续观看、定位当前及多个最近目录。
3. 加解密导入统一到候选发现组件，支持文件、目录和拖放；递归、格式过滤、去重、取消与问题汇总具有相同规则。
4. 加密输出可沿用源文件旁建议，也可采用统一目录并保留导入结构；支持多选输出和公开描述，完成项只读。
5. 重试先检查限定目标，只处理失败或取消项；新警告或输出变化交由用户查看计划后继续。开始按钮显示缺失条件。
6. 公开信息编辑保持草稿；保存才释放文件占用。写入失败保留草稿，恢复原媒体位置与观看意图，关闭或换片后不恢复旧目标。
7. 常用控制增加静音恢复、指定时间跳转、便捷倍速和快捷键帮助；宽窄布局支持侧栏调宽、折叠与表单滚动。

## 3. 根据工程能力确定的边界

### 3.1 加密结果进入观看

当前 SDK 3.4.0 的公开激活输入只有标题和创建意图，没有供插件携带文件路径新建 Document 的服务。当前交付流程为：

```text
加密完成 → 定位文件 / 复制路径 → 目标播放器拖入文件 / 粘贴路径 → 独立输入密码 → 播放
```

“一键新建播放器标签并交接文件”依赖 SDK 提供公开入口，保留为后续工作。这里不引入 Host 内部依赖，也不以进程级共享对象传递密码。

### 3.2 继续观看与目录记录

继续观看复用当前目录已扫描项目的历史过滤，并按最近观看时间排序；不创建跨目录独立播放列表。最近目录最多 10 个，兼容旧单目录字段；离线目录保留记录并说明不可访问，用户可移除记录。路径作为已有用户数据的一部分，不携带密码。

### 3.3 原生媒体的历史定位

真实样本发现：解码器刚绑定媒体时，可能尚未报告可定位，直接跳转会回到开头。恢复历史时在同一播放事务内复用已有表面恢复序列：临时静音准备解码、等待输出就绪、定位，再按意图继续播放或停在暂停首帧；准备有超时和取消补偿。

这是履行续播与编辑恢复所需的播放状态协调修正。容器格式、认证算法、加密解密、库版本及原生适配器继续复用。若恢复失败，界面应保留明确反馈，不能仅用“加载成功”宣称位置已经恢复。

## 4. 验证及后续

- 开发证据、提交批次、已知限制和真实媒体结果统一放在 [UX1 实施与验证记录](../reference/UX1-IMPLEMENTATION-AND-VALIDATION.md)。
- Headless 用于绑定、命令、布局和焦点边界；本地原生样本用于媒体恢复、全屏、标签切换及文件释放。
- 宿主 Dock 的真实拖拽、显示缩放组合和系统资源管理器/剪贴板的人工交互仍属于后续体验验收清单，不能由独立窗口测试代替。
- UX1.3 收藏、播放列表、外部字幕、书签和 A–B 循环继续作为按场景选择的候选，本轮不默认实现。
