# 视频工具：设置与维护、共用 LibVLC 改造方案 v1.0

> 日期：2026-09-28。状态：设计提案，尚未实施产品代码。
> 范围：在现有视频插件中加入一个设置与维护 Tool，并支持 Common 共用原生运行库。
> 交互演示使用虚构记录和模拟检测、保存结果，不读取或修改真实用户设置。

## 1. 目标和第一版范围

让一个入口承担跨页面默认设置、播放记录维护和运行环境排障，而不只提供一个 LibVLC 路径输入框。第一版包含四组：播放偏好、视频库偏好、记录管理、播放组件与诊断。

文件处理默认值作为后续增量：默认输出位置、加密保留目录结构、同名文件处理策略。现有加解密页面已有相应批次能力，本期不将其改为跨批次设置。

不集中当前媒体的音量、倍速、音轨和字幕控制，不转移批次密码、任务队列或当前输出路径，不增加保存密码、删除源文件、切换加密算法等选项。Common 共享文件，各插件及各文档的原生播放对象仍由原有所有者管理。

## 3. 入口、布局和作用范围

### 3.1 Tool 与页面内入口

- 名称：**视频工具 · 设置与维护**。
- 通过 `AddTool` 注册插件级模型；默认靠右，关闭行为为 Hide。View 重建不创建引擎、不重置草稿、不重复订阅。
- 用户从宿主现有 Tool 入口打开；安装后不强制展开，不常驻占用视频区域。
- 播放器和视频库的“设置与维护”入口，以及缺库提示里的“配置播放组件”，复用相同的设置视图与插件级状态。故障入口定位到运行库分组。
- 已检查的 SDK 提供贡献注册，但未提供插件直接打开指定 Tool 的公开导航端口。第一版不调用宿主内部 Dock API：页内入口在独立托管布局区展开同一设置内容，宽时并排、窄时位于视频区之外。不能用覆盖原生 HWND 的普通浮层，也不能为显示设置销毁或重新挂载播放表面。关闭后将焦点还给入口按钮。
- 独立 Tool 和内嵌设置分别创建 View，共用模型；不将一个 Control 同时挂到两个父节点。多处打开时显示相同草稿和保存状态。

### 3.2 布局

顶部只放播放组件摘要与“查看”入口；下面四个折叠分组。首次只展开播放偏好，重开保留本次分组状态，故障时展开运行库分组。建议初始停靠宽度 380–440 px，窄到 320 px 时控件换行。使用现有 VideoDocumentStyles 和宿主主题，支持键盘访问及深浅主题。

普通设置按字段自动保存，底部显示“保存中 / 已保存 / 保存失败，重试”；只有运行库使用显式“检测目录 / 保存配置”。清空历史采用局部确认区，不跳到另一个管理页面。

### 3.3 生效规则

| 类别 | 生效时间 | 对已打开页面的影响 |
| --- | --- | --- |
| 播放、视频库默认设置 | 保存后，新建播放器/视频库页面使用新快照 | 当前音量、倍速、目录和布局不被重置 |
| 播放历史记录开关 | 操作生效后，所有已开文档停止或恢复写入 | 不暂停播放；不自动删除已有记录 |
| 删除历史或最近目录记录 | 确认后立即广播变化 | 清理相关投影和缓存；不删除媒体、不切换当前目录 |
| 运行库配置 | 未尝试原生加载时，下次初始化采用；已尝试加载后需重启 | 当前运行库和播放会话不热切换 |

“保存成功”必须对应真实持久化完成。普通设置的保存失败保留草稿和重试入口；记录开关可先在内存中停止写入，失败时说明“本次已停止记录，重启后的偏好尚未保存”。

## 4. 配置项与默认值

### 4.1 播放偏好

| 项目 | 选择 | 新用户默认 | 说明 |
| --- | --- | --- | --- |
| 音量策略 | 记住上次 / 固定初始值 | 记住上次；无记录时 50% | 固定策略下才显示 0–100% 初始值；当前页面仍可临时调音量 |
| 倍速策略 | 记住上次 / 固定初始值 | 记住上次；无记录时 1.0× | 固定值使用现有六档 0.5/0.75/1/1.25/1.5/2 |
| 打开视频时 | 恢复上次位置 / 从头开始 | 恢复上次位置 | 已看完或失效历史从头；“仅加载”保持不自动起播，启动宿主不自动播放 |
| 快进/后退步长 | 5 / 10 / 30 秒 | 5 秒 | 同时用于快捷键和相对跳转命令；快捷键说明同步更新 |

固定初始值、最近实际使用值独立保存。正在播放的旧文档更新最近音量或倍速时，不能覆盖用户刚设置的新默认策略。第一版保留当前文档的连续播放开关，不新增全局自动连播默认值。

### 4.2 视频库偏好

| 项目 | 新用户默认 | 说明 |
| --- | --- | --- |
| 新窗口恢复上次目录 | 开启 | 关闭后新库为空；当前已打开目录不变 |
| 默认包含子目录 | 关闭 | 当前库仍可单独启用，修改当前库不反向覆盖默认值 |
| 默认排序 | 文件名、升序 | 复用现有文件名/公开标题/修改时间/最近播放时间及正逆序 |
| 恢复侧栏默认布局 | 操作项 | 重置后新库使用 400 px 期望宽度、侧栏打开、库设置折叠；窄窗仍服从自适应布局 |

目录选择、搜索、当前排序/筛选和本次递归扫描留在视频库页面。已有用户的当前保存值作为升级后的初始默认，避免升级时突然改动习惯。

### 4.3 记录管理

- “记录观看进度”：默认开启。关闭只停止新增/更新历史，不删除旧历史；旧历史是否用于续播由播放偏好独立控制。
- 显示历史条数和“清空播放历史”。确认文案：“清空 N 条观看记录？视频文件不会删除；此操作无法撤销。”清空不暂停当前视频。
- 显示最近目录列表，支持逐条移除和清空。只修改记录，当前浏览中的目录保持打开。
- 清除所选视频的历史仍保留在原视频库，便于上下文操作。
- 不新增可调的历史条数上限，沿用 1,000 条；最近目录沿用 10 条。

清空时使所有文档已有的待写历史失效，不能被定时回写或关页 flush 复活。之后再次明确打开/播放媒体，才开始新一轮历史记录。关闭记录期间积累的状态在重新开启后不补写，只记录之后发生的观看进度。

### 4.4 播放组件与诊断

来源只提供“自动选择（推荐）”与“指定目录”。自动选择的顺序为：

1. `AppContext.BaseDirectory/Common/libvlc`，作为宿主可执行目录下的 Common；不用当前工作目录，不硬编码开发机盘符。
2. 插件程序集目录下的 `native/win-x64/libvlc`。
3. 都不可用则只阻止播放，显示可操作的缺库提示。

Standalone 的 Common 相对于其可执行目录；没有 Common 时仍可使用其内置库或用户明确指定的目录。

指定目录只使用用户选定来源。无效时不静默替换来源；保存前复检，失败保留原配置。自动模式的 Common 预检失败时可选内置候选，并说明降级原因；一旦发生真实原生加载尝试，不再于同一进程盲目切换其他候选。

检查层次：绝对目录和可读性 → libvlc/libvlccore → x64 PE 架构 → 两个库及模块的兼容性 → MP4/WebM 解复用、视频解码、D3D11 输出和音频输出模块。目录存在或仅能播放音乐都不算视频可用。第一版以锁定的 3.0.23 运行库为验证基线，其他补丁版本要经过兼容验证后纳入；不只凭 3.x 主版本直接宣称支持。

Tool 检查只读文件元数据，不加载 DLL。无法通过元数据确定的版本/依赖不能显示“播放验证通过”。实际初始化后另报告加载成功/失败、真实路径和版本，并验证加载来源符合选择，防止同名 DLL 解析漂移。

详情分开显示：目录草稿、已保存选择、下次候选、当前已加载路径/版本，以及是否待重启。打开播放器页面已可能初始化原生后端，判断必须依据真实 LoadAttempted 状态。

Tool 可独立生成环境诊断摘要（平台、插件版本、运行库选择状态、稳定问题码）。具体媒体失败仍从原播放器“导出诊断”操作，避免 Tool 持有任意 Document 的播放服务或错误地导出另一标签页的数据。UI 可展示完整运行库路径；导出的诊断继续脱敏。

## 5. 模块拆分和持久化

### 5.1 建议新增的窄模块

- `Features/Settings/VideoSettingsTool.cs`、`VideoSettingsView.axaml`：组合四个设置分组、草稿、展开状态与保存反馈，不直接持有 LibVLC 或 Document。
- 播放/视频库默认值、记录维护、运行库状态分别通过窄接口访问。界面控制层不重新实现历史索引或原生路径判断。
- `PlaybackRuntimeResolver`：返回候选目录、来源和各候选检查结果。
- `PlaybackRuntimeStatus`：唯一持有实际选择、加载尝试和当前版本的事实；播放器与 Tool 读取同一份状态。
- `PlaybackEnvironmentDiagnostics`：无需播放实例即可生成环境摘要。

优先扩展现有 `SecretVideoUserDataStore` 的版本化文档，增加 defaults/recording/runtime 子记录，仍由同一个串行写入器提交。不另建第二个历史库或偏好缓存。内存提交与磁盘提交分别有修订号，UI 只对实际完成的修订显示保存成功；旧异步检查不能覆盖新草稿。

### 5.2 迁移

- 旧 schema v1 可读；缺失新字段时补默认。原音量/倍速成为“最近使用值”，策略默认为记住上次；目录与布局值保留。
- 旧历史和最近目录逐项保留，不在查看 Tool 时执行破坏性重写。
- 新 schema 采用 v2，版本号与插件发布版本分开。首轮部署保留可回滚的旧设置备份；备份只用于升级恢复，不参与日常历史自动恢复。记录清理规则覆盖受管理的升级备份，避免清空后自动恢复已删记录。
- JSON 损坏仍沿用可恢复读取方式，显示提示，不阻止设置面板打开或文件加解密。
- 插件级服务需取消检查、退订并等待已授权保存收口；不能因 Hide 关闭 Tool 而停止其他文档播放。

## 6. 两种交付布局

视频项目增加 `IncludeLibVlcRuntime`，默认 true，保持原自包含构建。false 时仍保留 `LibVLCSharp.dll` 和 `LibVLCSharp.Avalonia.dll`，只省去原生目录复制及资产声明；版本锁定不移除。

- 完整布局：随插件携带原生树，Common 不可用时可兜底。
- 共用布局：不携带原生树，使用 Common 或指定目录；缺库时插件仍可加载并打开设置、加密、解密页面。

两种构建使用独立输出与干净暂存目录，避免旧的 native 文件混入精简包。包校验需根据布局检查，不再无条件要求原生文件存在；托管桥接仍必须完整。外部路径不写进 manifest，安装/升级/卸载不删除或覆盖 Common。

运行库全目录共用，不混搭两处 DLL 或 modules。视频和音乐插件的库版本及真实加载路径需协调；不修改进程 PATH 或全局 DLL 搜索策略，不依赖另一插件先初始化。

## 7. 分阶段实施

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：设置骨架与策略存储 | Tool、四组视图、默认值快照、schema 迁移、保存反馈；用现有窗口入口展示 | 独立 Tool 不创建播放器；多处视图草稿一致；保存失败可恢复 |
| B：默认行为与记录维护 | 音量/倍速策略、续播、步长、视频库默认值、记录开关和清理通知 | 现有文档不被新默认值重置；隐私操作即时生效；历史不会被旧回调复活 |
| C：共用运行库与交付 | 候选探针、实际状态、Common 优先、指定目录、两种包布局 | 无原生包可进入设置；未加载可采用新配置；加载后明确待重启；音乐共存 |
| D：联调与收口 | Dock/浮动/多窗口、环境诊断、帮助文档、打包体积对比 | 功能与原生播放验证通过；记录真实安装/压缩体积，不用理论值代替 |

阶段 A–C 均保持可编译，并在自己的范围完成有意义的验证；阶段 D 补跨模块实际使用路径。当前仅提交设计与演示，不部署、不迁移用户设置、不修改 Common。

## 8. 验收场景

1. 无播放器时打开 Tool：可改默认值、查看历史、检测运行库，进程不因此加载 LibVLC。
2. 新用户默认行为与当前产品一致：记忆音量/倍速、历史续播、5 秒跳转、默认不递归、连续播放关闭。
3. 打开两个播放器和两个视频库，修改默认值：已开页面保持原行为，新开页面采用新值；旧文档写最近值不覆盖新默认值。
4. Tool 隐藏/浮动/View 重建后，未保存目录草稿、选中分组和错误消息保留，事件订阅不增长。
5. 模拟写入失败：不显示“已保存”；重试保存最新修订，旧响应不回退草稿。
6. 关闭记录后，全部已有文档及迟到回调停止新增历史；重新开启不补写禁用期间进度。
7. 清空历史/移除目录后立即刷新相关列表；旧定时器、关闭 flush 和恢复缓存不能复活；媒体文件保持原样。
8. Common 有效/缺失/模块不全/架构错误、内置有无、指定路径有效/无效，各分支状态一致。目录检查不绑定 DLL。
9. 保存配置前后区分当前和候选；成功或失败的加载尝试后均不在本进程热切换。
10. 两种包用干净输出生成，精简布局无原生残留，插件桥接文件及现有资源完整，缺库仍可打开 Tool 与加解密功能。
11. 网易云先播放、视频先播放、双方同时播放；真实视频覆盖 MP4/WebM、音频输出、字幕和 Seek，验证实际库来源及释放。
12. 多文档关闭、Dock 浮动/重建、全屏往返、页内设置展开，不替换原生播放对象，不丢位置或暂停状态。
13. 深浅主题、320/400/736 px 内容宽度、键盘操作与实际 Windows 缩放：无挤压、遮挡或不可到达按钮。
14. 环境诊断不要求媒体；文档诊断来自指定原页面，导出保持脱敏。

## 9. 演示范围

本轮交互演示包括四个折叠分组、记忆/固定默认值切换、即时保存反馈、历史清空确认、移除最近目录、目录选择和错误反馈、运行库配置保存后的待重启状态，以及环境诊断预览。

演示默认模拟一套已加载的 Common 运行库。目录选择器中的候选、观看记录和设置写入均为本地模拟；提供 Common 可用/仅内置可用/均缺失，以及已加载/未加载、保存失败等演示场景。它不证明真实 DLL 兼容性或播放能力，正式实现按上节验收。
