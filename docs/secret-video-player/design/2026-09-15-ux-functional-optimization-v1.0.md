## 1. 优化目标与范围

围绕三条用户流程优化：

1. **打开并观看**：选择视频、输入密码、播放和续播的行为明确且一致。
2. **找到并续播**：媒体库能快速找到目标、区分观看状态，并继续上次观看。
3. **批量处理并使用结果**：添加文件、配置、检查、执行、处理失败和使用结果形成完整流程。

本轮主要修改 View、ViewModel、用户偏好和应用流程协调。工程已有的四类 Document、公开 SDK 接入和服务组合可以继续复用。

### 1.1 本轮包含

- 播放入口、密码输入、加载状态和历史恢复的一致性。
- 媒体库首次使用、筛选、当前播放标识、观看进度及最近目录。
- 批量任务的输入效率、输出配置、预检展示、重试与结果操作。
- 播放器布局、常用控制、错误反馈及公开信息编辑体验。
- 对应行为测试、真实窗口验收和使用文档同步。

### 1.2 本轮边界

- 不以替换播放库、升级依赖、修改加密算法或 SECVID03 格式为目标。
- 继续保持输出不覆盖、源文件保留、失败及取消清理临时文件等现有行为。
- 密码继续属于当前 Document 会话，不随最近目录、历史或任务配置落盘，也不因新增跨页面入口而自动传播。
- 四种 Document 入口及稳定 Plugin、Document、Action ID 保持兼容；是否进一步整合入口可在后续版本讨论。
- 后台任务中心、关闭页面后继续执行、队列持久化属于独立扩展，不在第一、二批中引入。

本方案不构成对底层实现完整性的新审计结论；已有技术基线和验收状态仍以各自记录为准。

## 3. 现状与优化依据

| 编号 | 当前观察 | 用户影响 | 优化方向 |
| --- | --- | --- | --- |
| F01 | 单文件与媒体库主按钮只加载；媒体库双击、Enter 会直接播放 | 同一观看意图需要理解不同入口行为 | 统一主操作为播放或继续播放 |
| F02 | 选目录、密码、排序及历史管理集中在默认折叠的库设置中 | 首次使用和常用操作需要展开查找 | 主任务入口前置，低频设置折叠 |
| F03 | 历史 `InProgress` 显示为“播放中” | 未看完和此刻正在播放容易混淆 | 分离历史状态与实时播放标识 |
| F04 | 列表已有历史位置、时长数据，但主要展示状态与日期 | 用户不易判断看到了哪里 | 展示观看进度及继续观看入口 |
| F05 | “重试所选”主要重置状态，之后仍需检查并执行 | 按钮名称与操作结果存在落差 | 明确重试流程并减少重复操作 |
| F06 | 加密模型已有批次级预检问题集合，界面未像解密页一样展示独立详情 | 计数不足以说明如何修复批次问题 | 展示问题、涉及项目和建议动作 |
| F07 | 加密默认输出到源文件旁，主要通过逐项路径编辑调整 | 大批量统一整理输出较繁琐 | 增加统一目录和批量配置 |
| F08 | 结果主要展示状态和路径，缺少直接定位或播放入口 | 完成处理后仍需手动找到文件 | 补齐结果操作 |
| F09 | 进入公开信息编辑会卸载视频；取消编辑不恢复观看 | 查看或放弃修改也会打断观看 | 编辑草稿，保存时协调文件占用 |
| F10 | 侧栏宽度固定为 400，播放器有多组横向控制和固定最小宽度 | 窄 Dock 区域可能拥挤 | 验证宽窄布局并提供自适应方案 |

F10 是布局定义推导出的待验证风险，不作为已复现的遮挡缺陷。其余观察来自相关代码与界面绑定；实际可用性仍需通过完整用户流程验收。

## 4. 播放与续播交互

### 4.1 主操作规则

| 用户操作或媒体状态 | 目标行为 |
| --- | --- |
| 无历史，或已看完 | 主按钮显示“播放”，从头开始 |
| 存在有效的未完成历史 | 主按钮显示“继续播放 · 12:34”，恢复后播放 |
| 点击主按钮、双击列表项、按 Enter | 执行相同的播放意图 |
| 显式选择“从头播放” | 从零开始，不提前删除原历史；实际开始播放后更新历史 |
| 显式选择“仅加载” | 加载并定位，保持暂停，作为次级操作 |
| 手动上一项、下一项 | 对目标应用同一套历史恢复规则 |
| 连续播放自动进入下一项 | 从目标开头播放；保持默认关闭、列表末尾停止的现有规则 |
| 重新打开页面或恢复最近目录 | 只恢复浏览上下文，不自动发起观看 |

单文件入口与媒体库共用历史恢复策略和存储接口。只有文件身份匹配的历史才用于续播，沿用现有身份验证机制。

这会有意调整现有“主按钮加载后暂停”的产品行为；实施时同步更新使用说明和相关交互测试，保留明确命名的“仅加载”入口。

### 4.2 密码与加载状态

- 尚未输入密码时，在播放区域附近出现密码输入入口，并保留本次目标和播放方式。
- 输入完成后继续本次请求，不要求用户重新选择视频或再寻找播放按钮。
- 取消输入或加载时，清除待执行意图；更晚提交的选择覆盖旧请求。
- 页面使用“播放密码”“本批次密码”等明确文案，避免将共用密码与公开元数据混淆。
- 区分等待输入、加载中、播放中、暂停和失败；加载中支持取消，并防止重复请求提交。
- 无法可靠区分密码错误与内容认证失败时，保留准确的合并说明，不制造确定性判断。

### 4.3 验收标准

- 初次使用无需阅读帮助即可完成一次播放。
- 同一视频通过按钮、双击和 Enter 进入时，起播位置和播放状态一致。
- 输入密码后只继续最新有效的请求，取消后不发生延迟起播。
- 单文件和媒体库对同一文件应用一致的历史规则。

## 5. 媒体库日常使用

### 5.1 信息布局

- 空页面直接提供“选择视频文件夹”，并简要说明支持的文件类型。
- 顶部常驻目录入口、搜索、排序和“全部／未看完／已看完”筛选。
- 递归扫描、历史清理等设置放入折叠区域；播放所需的密码入口可在需要时直接出现。
- 列表保持虚拟化，不因新增进度展示对所有媒体执行解锁或完整解析。

### 5.2 播放状态和进度

- 历史状态采用“未播放／未看完／已看完”。
- 当前播放文件单独标识，并区分正在播放与暂停；选中样式仍表达列表选择。
- 有可信历史数据时展示“12:34 / 45:00”和进度；没有时长时不显示虚假的零值或百分比。
- 增加“定位当前播放项”；若当前项被筛选隐藏，说明原因并提供清除筛选入口。
- 增加显式“从头播放”，减少通过清除历史实现重看的绕行。

### 5.3 第二批新增能力

- 最近使用的多个目录：快速切换、定位失效目录、移除记录。
- “继续观看”入口：从现有历史中提取可访问且未完成的项目。
- 保存侧栏宽度等普通界面偏好，沿用已有用户数据存储与兼容读取方式。

第一、二批继续保持“连续播放按当前筛选列表前进”的既有语义。独立播放列表放入后续扩展，届时明确其与搜索结果的区别。

### 5.4 验收标准

- 用户能区分所选项目、当前播放项目和历史未看完项目。
- 搜索、筛选、目录监听和新增展示不打断当前视频。
- 现有千项列表场景仍可用；进度展示不会触发逐文件解锁。
- 最近目录不可访问时提供恢复入口，不阻止选择其他目录。

## 6. 批量任务流程

### 6.1 添加与配置

- 支持拖入文件和添加目录；重复文件去重，目录递归规则明确，无法访问的项目给出摘要。
- 加密端提供“源文件旁／统一输出目录”选项；目录添加场景可选择保留子目录结构。
- 支持多选批量设置输出规则及适用的公开信息，逐项覆盖仍然保留。
- 检查结果展示最终输出路径；自动追加编号时展示实际名称。
- 修改影响执行的配置后，使旧计划失效，并明确显示“配置已变化，需要重新检查”。

### 6.2 检查与执行

界面按以下阶段组织主操作：

```text
待配置 → 检查中 → 检查结果 → 执行中 → 完成 / 部分失败 / 已取消
```

- 待配置时说明缺失条件，如尚未选择输出目录、密码长度不足、确认密码不一致。
- 检查结果同时显示数量和问题详情，支持定位受影响项目。
- 加密页与解密页统一展示批次级问题、单项问题和建议动作。
- 运行期间突出当前文件、总体进度及成功／失败数量；“取消当前”和“取消全部”保留清晰区别。
- 第一、二批沿用现有关闭页面会取消工作、放弃等待项的生命周期语义，并让运行中的页面明确表达这一点。

### 6.3 重试规则

- “重试所选”处理选中的失败或取消项，“重试全部”只处理可重试项。
- 重试先重新检查输入和输出环境，继续跳过成功项。
- 没有阻止项、待处理警告或输出变化时，可直接执行此次重试。
- 出现警告、阻止或输出路径变化时，停在检查结果，明确列出问题与可执行范围，再由用户开始执行。
- 不绕过已有预检、不覆盖文件，也不把仍处于成功状态的项目重新加入执行。

### 6.4 结果操作

- 成功项提供“定位文件”；统一输出时提供“打开输出目录”。
- 加密结果提供“播放”或“打开所在媒体库”，通过公开 SDK 支持的方式交接文件上下文。
- 新 Document 按自身会话规则输入密码，不隐式继承其他 Document 的密码。
- 失败项可筛选，错误旁提供适用的修改密码、修改输出目录、重新检查等动作。
- 清空已完成仅移除界面中的记录，文案明确表达这一点。

### 6.5 验收标准

- 一批文件可统一配置输出，无需逐条手填完整路径。
- 批次不能执行时，用户能够看到具体原因及处理入口。
- 重试不重复处理成功项，环境变化后仍执行检查与冲突策略。
- 用户从成功结果可以直接找到文件或进入观看流程。

## 7. 播放器布局与操作效率

### 7.1 常用操作

- 常驻播放／暂停、进度、音量及全屏；倍速保留便捷入口。
- 音轨、字幕轨和诊断按需展开，正常观看时减少常驻信息。
- 增加静音与恢复原音量、指定时间跳转、快捷键提示。
- 播放成功后将路径和密码表单收起为简洁的当前视频信息，保留更换入口。
- 快捷键继续尊重输入控件焦点，不抢占文本编辑、列表与下拉选择。

### 7.2 宽窄布局

- 媒体库侧栏支持调整宽度，窄区域下允许折叠或临时展开。
- 控制栏根据可用空间换行或将次级操作收入菜单，保留主要操作可达。
- 在宽窗口、760 × 600 参考尺寸、较窄 Dock 文档区及常用缩放比例下验证。
- 当前视频表面由原生控件承载。悬浮控件是否能覆盖视频必须单独验证，第一轮优先调整周边布局。
- 全屏继续使用现有窗口内容区呈现契约，验证进入、退出与切换标签后的播放状态。

现有界面测试主要检查构建、尺寸及控件资源，不能独立证明控件没有遮挡或操作可达；本项需要真实窗口验证。

## 8. 公开信息编辑与错误恢复

### 8.1 编辑流程

1. 打开编辑器时创建标题、描述草稿，保持当前观看状态。
2. 取消编辑时丢弃草稿，保持原播放位置与状态。
3. 提交保存时记录位置、播放／暂停、倍速和可恢复轨道，再协调媒体释放与写入。
4. 保存成功后，使用当前会话中仍有效的凭据恢复同一媒体及原状态。
5. 写入失败时保留草稿、说明原因；尝试恢复原媒体，恢复失败则提供重试入口。
6. 关闭页面或用户已经切换目标时，不执行过期的恢复操作。

继续使用现有公开区编辑能力；实施前验证文件占用与恢复顺序，不修改视频主体格式。

### 8.2 错误反馈

- 优先展示用户可理解的问题和下一步操作，详细代码及诊断放入次级信息。
- 单文件与媒体库使用已有类型化失败结果，减少上层通用文本覆盖具体问题的情况。
- 保留当前有效媒体与输入上下文，让修复后可以继续操作。
- 区分取消、加载失败、文件不可访问和运行环境不可用，避免正常取消显示为故障。

## 9. 实施批次与优先顺序

P0 表示本轮优先处理，P1 表示随后处理，P2 表示候选扩展；这是产品迭代优先级，不是故障严重等级。

| --- | --- | --- | --- |

| UX1.1 理顺现有交互 | 批次预检详情、禁用原因和重试行为 | P0 | 复用现有预检、计划失效和执行接口 |
| UX1.1 理顺现有交互 | 公开信息编辑恢复、统一错误反馈 | P1 | 验证媒体占用、取消与恢复顺序 |
| UX1.2 补齐高频功能 | 单文件共享续播、列表进度、继续观看、多个最近目录 | P1 | UX1.1 播放语义确定后实施 |

| UX1.3 场景扩展 | 收藏、独立播放列表、外部字幕、时间书签、A–B 循环 | P2 | 按实际观看或学习场景选择，另列详细方案 |

建议从 UX1.1 的媒体库选片与播放入口开始，同时处理批次预检和重试。UX1.3 是候选清单，不要求一次性实现全部功能。

### 10.2 验证矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| 首次进入媒体库 | 可直接选择目录；无密码时能顺畅进入输入与播放流程 |
| 不同入口打开同一视频 | 起播位置及播放状态符合第 4 节规则 |
| 快速切换、取消加载、关闭标签 | 旧请求不覆盖新状态，不发生关闭后的起播 |
| 未播放、未看完、已看完与正在播放 | 显示准确，可区分历史状态与实时状态 |
| 搜索和目录变化 | 选择、导航、当前播放和连续播放符合既定规则 |
| 密码不一致、目录不可写、输出冲突 | 展示准确原因，提供对应修复入口 |
| 部分失败、取消、重试 | 成功项保持完成；其余项目重新检查后处理 |
| 编辑取消、保存成功、保存失败 | 草稿和原观看状态按规则处理 |
| 宽窄布局、主题、缩放、全屏和 Dock 切换 | 主要控件可达、文字可读、视频及操作正常 |
| 多个播放器或任务标签 | 各自播放、密码、任务状态保持隔离 |

实施时为改变的交互语义补充行为测试，复用既有业务和宿主集成测试。涉及原生视频表面、真实播放及文件占用的部分必须补充交互式 Windows 验证；不以 Headless 布局测试替代真实体验验收。实际命令以 [部署和验收指南](../../deployment-and-release.md) 为准。
